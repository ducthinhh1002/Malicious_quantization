# Review run `blind_20260922_125330_963252`

## Trạng thái dữ liệu

Đây là **run chưa hoàn tất**, không phải output đủ để kết luận hiệu quả attack. Thư mục chỉ có
`manifest.json`, `search.csv`, `search.json` và 14 thư mục branch. Các file bắt buộc sau chưa tồn tại:

- `selection_frozen.json`
- `report.json`
- `owner_evaluation.json`
- `watermark_retention.csv`
- `quality_summary.csv`

Run dừng giữa `natural_qat_scale_w8_c1.0`: `updates.json` ghi 900/1000 update và branch chưa có
`selection.json`. Vì owner evaluation chỉ chạy sau khi mọi branch được freeze, output này không có
bit accuracy, TPR hoặc evasion rate. Không được diễn giải proxy reconstruction như watermark removal.

## Những gì proxy hiện tại cho biết

- `reconstruction W4` giảm objective từ `5.414e-4` xuống tốt nhất `2.111e-4` ở bước 600,
  với PSNR `37.60 dB`, SSIM `0.9743`. Bước 1000 hơi kém hơn (`2.142e-4`), nên checkpoint
  selection hoạt động đúng.
- `block_reconstruction W4` đạt `2.130e-4` ở bước 1000, gần như không hơn reconstruction thường
  (`2.111e-4`) dù có cơ chế và chi phí phức tạp hơn.
- `natural_residual W8` giảm proxy từ `0.04275` xuống `0.03830`, nhưng PSNR giảm từ `57.09` xuống
  `38.15 dB`. Quality gate vẫn đạt, song đây là đánh đổi thị giác đáng kể so với mức giảm proxy.
- `natural_residual_qat W8` kết thúc ở `0.03844`, hơi kém residual rounding theo proxy. Nó làm đổi
  khoảng `2.36%` code so với RTN, nên vẫn là ablation cơ chế khác biệt cần giữ cho đến khi có owner metric.
- Các nhánh `natural_rounding`, `natural_rounding_scale` và `natural_qat_purification` cho đường cong
  rất gần nhau ở W8. Chưa có bằng chứng owner-side để biện minh chạy cả ba trong vòng mặc định.
- `block_reconstruction W8` tăng PSNR lên `60.68 dB`; đây chủ yếu là purification/reconstruction tốt,
  chưa phải bằng chứng attack mạnh hơn.

## Nguyên nhân chậm

Manifest xác nhận GPU là NVIDIA H200 nhưng auto runtime chọn `gen_batch_size=1` và
`eval_batch_size=1`. Mỗi checkpoint đánh giá 256 ảnh tự nhiên tuần tự. Đồng thời protocol khai báo
24 branch, trong đó 22 branch có tối ưu, tối đa 22.000 update. Run chưa đến các branch W4 natural và
hai FP32 controls trước khi snapshot được lấy.

## Sửa đổi sau review

1. Auto batching CUDA bắt đầu ở batch 8 cho diffusion và batch 32 cho VAE/metrics, sau đó giảm một
   nửa khi gặp CUDA OOM. Cách này dựa trên allocation thật thay vì ước lượng tĩnh đã chọn sai batch 1.
2. Launcher mặc định dùng bộ `focused`: `fixed_ptq`, `reconstruction`, `natural_residual`,
   `natural_residual_qat`, và `natural_full_finetune`. Với W8/W4, số training branch giảm từ 24 xuống 9.
   Bộ `full` vẫn giữ toàn bộ ablation.
3. W4 chạy trước W8 trong từng threat model để một run bị gián đoạn vẫn thu được low-bit condition
   quan trọng trước.
4. Profile launcher bật TF32 cho FP32 convolution/matmul trên GPU hỗ trợ. Đây là phép tính chuẩn thường
   dùng cho huấn luyện deep learning nhưng không bitwise-equivalent với strict FP32; lựa chọn được ghi
   vào manifest. Dùng `--cuda-math strict` khi cần đối chiếu số học nghiêm ngặt.
5. `run_status.json` được cập nhật sau từng branch cùng thời gian chạy, branch hiện tại và lỗi, nên run
   chưa hoàn tất vẫn phân tích được chi phí.
6. Checkpoint discriminator của nhánh GAN được chuyển sang artifact directory nặng; report directory
   chỉ giữ JSON/CSV.

## Cách chạy sau sửa đổi

Focused run, phù hợp để lấy owner result trước:

```bash
bash run_blind_quantization.sh
```

Toàn bộ ablation sau khi focused run đã cho kết quả có triển vọng:

```bash
WMQ_METHOD_SET=full bash run_blind_quantization.sh
```

Suite mặc định cũng chuyển sang `focused`. Muốn chạy toàn bộ:

```bash
bash run_blind_suite.sh --profile full
```

Run cũ không thể suy ra watermark retention và không nên đưa vào bảng kết quả paper. Dataset COCO và
model cache vẫn được tái sử dụng khi bắt đầu run mới.
