# C00 code and runtime audit — October 11, 2026

**Finding:** The original C00 used the same Diffusers trainer as C10 and is affected by the confirmed pre-fix gradient-clipping iterator bug. The shared trainer is now fixed for future runs; the old C00 checkpoint has not been retrained. No additional C00-specific defect was identified in the checks below.

| Check | Evidence |
|---|---|
| Training source | `run_c00_baseline.sh` builds C00 from `data/raw/clean_train`, with `adapt_train.txt`; no watermarked or regenerated data in this route. |
| Image/caption pairing | Full 5,000-row audit reports zero C00 mismatches. |
| Training | SD1.4, rank 4, LR 1e-5, batch 8, accumulation 1, nominal 20,000 steps, seed 0, fp16; same scientific settings as C10. |
| Checkpoint selection | 1,000 `clean_val` images; minimum unseen MSE selects checkpoint 20,000, MSE 0.1497900049. |
| Adapter | 256 finite tensors; all optimizer states record 19,999 updates at nominal step 20,000. A skipped fp16 update is a possible explanation, not a reconstructed cause. |
| Generation replay | Four images regenerated with the selected adapter, original prompts/seeds, PNDM, CFG 7.5, 50 steps and batch 4 match stored images exactly. |
| Adapter activation | Disabling LoRA changes the four images: pixel MAE 47.88, 46.16, 49.66, 29.84 on the 0–255 scale. |
| Detection | 46/5,000 = 0.92% at the same fixed threshold 0.04637297987937927. For clean-trained C00 this is an expected false-positive rate near calibration FPR, not evidence that C00 should have been radioactive. |
