# C10 implementation audit — October 11, 2026

## Finding

C10 follows the principal data, training, checkpoint-selection, generation, and frozen-detector requirements in the [plan](../THREAT_MODEL_radioactive_watermark_laundering.md). However, a **confirmed gradient-clipping defect** was found in the pinned Diffusers training example. Therefore, the implementation cannot be described as defect-free. The defect has been corrected for future runs; its contribution to the 3.24% TPR remains unmeasured.

The four-image generation replay matches the original C10 outputs exactly, confirming that the selected adapter and documented generation settings reproduce the sampled outputs. The low result is not explained by accidentally generating those images from the unadapted base model.

## Confirmed defect and correction

Server file: `/root/workspace/serum/third_party/diffusers/examples/text_to_image/train_text_to_image_lora.py`.

- Line 563 originally assigns `lora_layers = filter(lambda p: p.requires_grad, unet.parameters())`.
- Optimizer construction consumes this one-shot iterator.
- Lines 930–931 reuse it for `accelerator.clip_grad_norm_`; it is already exhausted. Gradient clipping consequently receives no parameters.
- Optimizer parameter groups still contain the parameters and update them. The defect disables clipping; it does **not** disable LoRA training.

Minimal reproduction: a parameter with gradient 100 retains gradient 100 and returns clipping norm 0 after optimizer construction consumes the iterator. Replacing the iterator with a list returns norm 100 and clips the gradient to 1. The corrected list also passes two consecutive checks through `Accelerator.clip_grad_norm_` with optimizer updates between them.

Applied correction:

```python
lora_layers = [p for p in unet.parameters() if p.requires_grad]
```

The patched training file compiles. [Patch](report_seed0_evidence/lora_gradient_clipping_fix.patch) and [validation/provenance](report_seed0_evidence/lora_gradient_clipping_fix.json) record the exact change and before/after hashes. This is a local modification on top of Diffusers commit `1d5d056ecff3a8c1d887a7dd1aa66ca4a0323458`; the original Git commit alone no longer describes the working tree.

All six existing seed-0 students were trained with the previous code. Existing checkpoints, outputs, and metrics remain unchanged and must be labeled as pre-fix results. Actual training gradient norms were not logged, so the frequency and magnitude of clipping that would have occurred cannot be reconstructed. A clipped versus unclipped training comparison is needed to measure the defect's effect; the defect alone does not explain the published TPR gap.

## New runtime evidence

[Machine-readable audit](report_seed0_evidence/c10_deep_audit_2026-10-11.json) records:

- 256 finite adapter tensors; selected adapter SHA-256 `7de73a00d31123c75b0ea37a5be045b69ca6ce9a1713d8f5675412355a6ab147`.
- All 256 optimizer states report 19,998 updates at nominal checkpoint 20,000. This is consistent with two skipped fp16 updates, but the precise cause was not reconstructed. It does not imply that training failed; 2/20,000 is 0.01% of the nominal budget.
- All four replay images match the original output exactly (pixel MAE 0).
- Disabling LoRA yields pixel MAEs of 47.25, 41.77, 55.23, and 38.77 relative to those original images on the 0–255 scale. These are execution diagnostics, not utility metrics.

The original C10 output directory predates the generation-manifest addition and has no `generation_manifest.json`. The replay provides direct evidence for four outputs, not proof of provenance for all 5,000. Future runs should retain the manifest and add immutable adapter/base revision hashes.

## Interpretation and next controlled experiment

The correct current statement is: **C10 largely implements the plan, but the original trainer had a verified clipping defect; the cause of weak radioactive transfer remains unresolved.** Earlier statements that no defect had been found are superseded by this audit.

The next informative experiment is a fresh C10 run using the corrected trainer, identical data/init/seed/hyperparameters, and a new output directory. Preserve the original run as the unclipped comparison; select checkpoints by the same validation MSE and score with the same frozen threshold. If repeating the full 2×2 study, rerun all conditions consistently with the corrected trainer rather than mixing corrected C10 with pre-fix C11.

This audit did not launch a new 20,000-step training run. It does not establish that correcting clipping will recover the 52.30% result cited in the plan. Remaining differences in the exact SERUM key/checkpoint, author training recipe, prompts, dependencies, and teacher weights documented in the [reproduction audit](RADIOACTIVITY_REPRODUCTION_AUDIT.md) still require investigation.
